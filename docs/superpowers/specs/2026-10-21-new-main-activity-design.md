# NewMainActivity 首页设计

## 目标与范围

在 CleanMyTV 现有包名（由 `launcherApplicationId` 决定）内新建 `NewMainActivity`，让它接管标准 HOME 和电视应用入口。用户想保留当前首页顶部的时钟、日期、问候语和按钮外观及单击用途，只将中间区域替换为「设计小米电视桌面」的 MiFlow 应用菜单：标题、应用与置顶数量、玻璃卡片网格，并移植置顶和移动交互。新页面不启用旧版 Settings 按钮长按菜单；旧 `MainActivity` 保持可显式启动，便于回退。

本次不移植 MiFlow 的主题、文件管理、开机启动、底部导航或设置页；不修改包名、无障碍服务和小米桌面状态。

## 页面和入口

使用独立的 `activity_new_main.xml` 与 `NewMainActivity`，不把新交互塞进旧首页的程序坞/排序代码。新页面顶部复用现有字体、尺寸、按钮样式和配置控制的显隐。Inputs、Wi-Fi、Settings、Library 保留当前单击用途；顶部 Reorder 按钮进入新网格的移动选择流程。Settings 仅单击打开系统设置。中间采用标题「你的应用」、应用/置顶计数、简短说明和可滚动卡片网格；宽屏六列，较窄屏幕四列。卡片显示图标、名称和置顶标记，获取焦点时出现浅色玻璃高亮与轻微放大，遥控器方向键在顶部和网格之间可导航。

Manifest 将 HOME、DEFAULT 与 LEANBACK_LAUNCHER 入口由旧 `MainActivity` 转给 `NewMainActivity`，沿用旧 HOME 的 singleTask 等配置；旧页仍 exported，允许用显式组件启动。系统是否保留此前的默认 HOME 选择取决于电视固件，安装后需在真机核验 Home 键。

## 应用数据和交互

扫描系统的 LEANBACK_LAUNCHER 与 LAUNCHER 活动，以组件名去重，优先采用电视入口；排除自身、禁用或不可导出的活动。初始显示全部可启动应用，用户在原应用库中明确移出首页的应用除外；原应用库仍可将其加回。启动应用时使用组件 Intent，包变化或返回首页时刷新列表。

新页面使用独立的持久化顺序和置顶集合，不读写旧 `order.txt`，以免改变旧首页。恢复列表时先按已存顺序排列已安装应用，再追加新应用；置顶应用在前，普通应用随后，各组内部保持顺序；已卸载应用从当前视图清除。长按确定或按菜单键打开卡片操作菜单：置顶/取消置顶、移动位置、应用信息。顶部 Reorder 按钮让用户选择待移动卡片。移动模式用方向键与相邻卡片换位，仅在同一置顶组内移动；确定保存，返回取消并恢复原顺序。置顶变化立即保存并重新分组。页面显示当前操作提示，焦点留在当前应用上。

## 验收

先用纯 JVM 测试覆盖：首次排序、重载顺序、应用增删、置顶分组、禁止跨组移动、取消移动恢复。然后运行本项目现有单元测试和 debug APK 构建，并检查合并后的 Manifest 只有 `NewMainActivity` 响应 HOME。若本机可用设备连接，再检验遥控器的焦点、启动、长按/菜单、保存/取消及 Home 键；没有设备时将真机部分如实列为待验证。
